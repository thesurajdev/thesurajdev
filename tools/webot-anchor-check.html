When a section ID changes, its old jump links can quietly stop working. Webot helps you find those broken connections across your own site.

Scan rendered pages

Checks your published pages and posts using rendered HTML, including navigation, theme output and page-builder content.

Go straight to the fix

Use one-click edit links to open the page containing the broken link and make the correction.

Schedule weekly checks

Enable optional weekly scans and get a dashboard notice when a scan finds issues to review.

⇩

Export your results

Download the full scan log as CSV for reporting, documentation or your own QA workflow.

Handle dynamic IDs

Add IDs created after page load to an ignore list, so known JavaScript-generated anchors don't clutter your results.

Know what needs attention.

Each result is labelled so you can distinguish a valid anchor from a broken destination or a page that could not be checked.

  • ✓OK — the target ID exists on the destination page.
  • ✓Broken — the target ID or named anchor was not found.
  • ✓Failed / Skipped / Unchecked — see the scan outcome rather than silently losing a page.

Good to know

Frequently asked questions.

Does it check links to other websites?

No. Webot Anchor Check checks internal links that point to fragments on your own site.

Will it change my content or affect visitors?

No content is edited. The plugin reads your pages and records results when you start a scan or when an optional scheduled scan runs. Visitors are not affected by the scan interface.

Why might an anchor that works be reported as broken?

Some tabs, accordions and sliders create IDs with JavaScript after the page loads. The scanner reads server-rendered HTML. Add those known IDs to the ignore list in Tools → Anchor Check → Settings.

What does the plugin store?

The latest scan results, settings and short-lived cached ID lists are stored in your own WordPress database. The plugin does not send data to an external service; its uninstall routine removes its stored data.

What are the requirements?

WordPress 5.8 or later and PHP 7.4 or later. The server must have the PHP DOM extension enabled for HTML parsing.
